# logicxkit/data — packaged record templates, native donors, parameter and translation tables

The files here come from four origins: Logic's saves of the public corpus, one tracking take,
measurements of Logic's own plug-ins, and hand-made maps. None is third-party plug-in state or an
AU parameter table (`resources/data/README.md`); those live under the data root
(`LOGICXKIT_DATA`), which adds what is not here; a file here wins over the root's of the same name.

`donors/` and the record templates in `logic/` are generated by `bin/regen_data.py` from the
public golden corpus (Logic's own saves of a blank project, tracked under `tests/corpus/`), and
hold only Logic's own structures: record templates for a fresh track, a section, a send and a
stack, and donor slots for Logic's native plug-ins — the inserts of `inserts-native-all-logic`,
the output plug-ins of `master-track-limiter-logic` and every plug-in of the `stockfx-*` saves,
a mono record each and a stereo one beside it where Logic writes another length.

`logic/params-<type>.json` (and `params-<type>v<variant>.json` for a type two plug-ins share) are
parameter tables of Logic's own plug-ins: each float index named by matching a save at defaults
against one with every slider in Logic's Controls view moved (`stockfx-*`), read by
`services/plugin_params`. `regen_data.py` leaves them alone.

`translate/` holds the translation maps `logic settings` and `replace-plugin --translate` read
(`services/translate`): one per plug-in and family, naming its parameters in the family's
vocabulary; a native map's `automation` table is its sliders sampled position by position.

`logic/rba-sequence-12.3.1.json` is not from the corpus: the RBA Sequence triple and the flex
marker block shapes Logic writes on an audio quantize, taken from a tracking take with every
per-region field zeroed (`services/flexmarkers.py` sets them). `regen_data.py` leaves it alone.

Drum maps live in groovebin (`groovebin.maps`), not here.
