# How each command was checked

What each command was measured against in Logic, and where it stops: the answer to **can I point
this command at a real Logic project today?** What the commands do, in plain words, is in
[CAPABILITIES.md](CAPABILITIES.md).

Read the table, then the defect list, for anything you plan to run. Each row says what it was
measured against and when. All of it is macOS-only: the writers target Logic Pro's own project
format, and "confirmed" means the output was opened in Logic Pro itself. The measurements
dated to 2026-09-30 are on projects Logic 12.3.1 saved (file format 2513); those dated from
2026-10-01 on are Logic 12.4's, in the same format. Logic 12.4 re-saved each of the 61 public copies a writer made, with the record list
12.3.1's re-save has and the goldens that hold that one (2026-10-01). Every writer refuses a
project in any other format, unless its catch below says it writes one.

The table is **generated from `src/logicxkit/logic/_capabilities.py`**, its rows declared in
`_capabilities_table.py` — change a level there, not here. `bin/run logic capabilities -v`
prints it with the catch per command, and `tests/logic/test_capabilities.py` fails when a
subcommand has no entry or the two drift apart.

## Confidence levels

| Level | Means |
|---|---|
| **CONFIRMED** | Output was opened in Logic and the change was there. The save that proves it still exists. |
| **CLAIMED** | A doc says it was confirmed, but the save is gone or the code has changed since. |
| **DERIVED** | Byte layout reasoned from reads and diffs. Never opened in Logic. |
| **BROKEN** | Has a defect reproduced on a real Logic project. |

A command being in `--help` is not evidence of anything.

The controlled Logic saves these confirmations were measured against are Logic-authored project
files and are not redistributable, so a clone carries none of them; `resources/README.md` says
how to stage your own.

## The catch, per command

<!-- generated from src/logicxkit/logic/_capabilities.py — edit there, not here -->

### `project` `manifest` `diff` `decode` `neural` `recdiff`

`project`'s "channels with inserts" counts `.cst` labels, not loaded plugins.

### `plugins`

Names every slot's plug-in — Logic's own by its slot header, with or without a float block: its 27 instruments, its nine MIDI effects (marked as such), its effects and Pedalboard's 35 stompboxes as pedals, one Logic 12.4 save of each (`instrument-*-logic`, 2026-10-05/06) — and a third-party one by the AU component identity in its embedded preset, and checks the third-party ones against `auval -a`, whose scan is kept for a day while the Components folders stay as they are (`--rescan` runs it again). A scan that leaves out a plug-in a Components folder holds is named as such, not kept, and run again when a kept one is the scan that lacks it: auval once listed only part of what was installed, while the system was still registering Audio Units (2026-10-04). A missing verdict has not yet been compared with Logic's own missing-plug-in dialog. A component whose bundle has gone bad stays in the registry, and Logic itself opened such a project without an alert (FabFilter Pro-C 2 disabled by hand, 2026-09-16); `--validate` opens each listed component with auval -v and reports it broken.

### `regions`

Every MIDI and audio region, numbered, with its track, start, mute, loop and fades; an audio region's file record (name, format, frames, rate, channels, bits), its first frame and length in frames. Read from Logic's imports of two WAVs onto a blank-born project (2026-09-13) and Logic's own move, trim, split, mute, rename, loop, fade and import saves of one (2026-09-15, the `regions-a*` goldens): an entry pairs with its region record by slot word and piece number and with its file by slot on every project on hand with audio, so a split's second piece reads its own record. Names are UTF-8 with a byte length (region), UTF-16 LE with a unit count (file): `Snare 🥁`, `Pad — é` and `v040-日本.wav` read back as Logic wrote them. `--audio` copies a PCM WAV at the project's rate into the bundle and writes the file, region and container records held field for field to Logic's own first, second and third imports; Logic re-saved two imports written onto a blank-born project with every region record, entry and registry id as written, rewriting only each file's folder path and size, and one word of the stereo file, on load (2026-09-14). It writes onto a project with no audio regions or one whose regions are laid out as Logic's imports and splits leave them (n file records numbered 0, 4, … 4(n-1) with their region records, an ordinal/link chain in file order, one registry entry each), and refuses any other layout, a WAV whose name the project already holds, and other rates and formats. The track selection is not moved. `--move`, `--trim`, `--split`, `--loop`, `--mute`, `--rename`, `--fade-in` and `--fade-out` write the fields Logic's own edits changed, and Logic re-saved a copy carrying all eight on audio and a move, both trims, a split and loops on MIDI with every region, record, entry and the split pieces' fields as written (2026-09-15, `regions-audio-edits-*` and `regions-midi-edits-*`). A split's second piece needs the file record's region count raised — Logic loads that many — and a MIDI piece plays its sequence from an offset, which the MIDI edits then refuse; an audio region's loop length is one measurement (its length in ticks times 1000). A split of a faded region moves the fade-out and the selection to the piece as Logic's own split did, entry for entry, and Logic re-saved ours with both entries as written (Logic 12.4, 2026-10-28, `regions-c01`..`c03`); a region crossfaded at its start splits as Logic's own split did on the three entries byte for byte — the crossfade stays on the parent, the piece gets none, the edited bit moves with the selection (Logic 13.0, 2026-11-06, `regions-c04`); one crossfaded at its end is refused, unmeasured. The inspector's Gain, Delay, Transpose, Fine Tune and Reverse, the Fade-Out type, the crossfade with the region over it and a region's colour read what Logic's own edits of one region wrote (2026-09-15, the `regions-b*` goldens; gain is a tens byte plus a signed five-bit remainder); `--gain`, `--delay`, `--transpose`, `--fine-tune`, `--reverse`, `--fade-out N=MS:CURVE:TYPE`, `--crossfade` and `--colour` write those fields the way Logic did, entry for entry on the save before its own, and Logic re-saved a copy carrying all of them with every field as written (`regions-params-*`), setting one more bit beside the crossfade's. Transpose on an unflexed region made Logic flex the track, which the writer does not; Logic kept the value on load, but whether it plays transposed is unheard. `--to-track N=TRACK` puts a region on another audio track where it is in time, writing the entry's track object and row — the two fields Logic's own drag of a piece onto another track changed, its record untouched (`vocal-pieces-moved-logic`, Logic 12.4, 2026-10-25) — and the destination row flagged as holding a region, as Logic 13.0's re-save of a move onto a bare row left it (`split-sections-ours-resave-13-0-logic`, 2026-11-13); a track whose last region leaves keeps its row's flags, unmeasured — and Logic 12.4 opened and saved a set's copy carrying `split-sections`' moves, which are this writer's, with every entry as written (2026-10-25). On a Logic 13.0 save (format 2514) every write here lands as written: the eight audio edits, the MIDI move, trim, split, loops and rename, the parameters and an import, written onto 13.0 saves, list and read as Logic 13.0's own edits of the same project, and Logic 13.0 re-saved each copy with every record as written but a touched piece's number byte and the row mark (2026-11-12, `regions-d05`..`d20`: `regions-d14-edits-ours-resave-13-0-logic`, `regions-d16-midi-ours-resave-13-0-logic`, `regions-d18-params-ours-resave-13-0-logic`, `regions-d20-import-ours-resave-13-0-logic`). Logic's own 13.0 edits also keep a length change's cut-off tail as an unreferenced record and stamp bookkeeping bytes this tool leaves to Logic; its re-save of the import rewrote the file record for its own copy of the WAV, gave it 13.0's leading word and set the row's content flags — `--audio` writes the project's leading word and the row flags itself since, so a fresh import differs from Logic's own in the words of Logic's copy of the WAV and the selection alone (2026-11-12). Also writes Logic 13.0's saves (file format 2514).

### `markers`

Reads the marker track — a marker's bar, name and length — matching Logic's Marker List on its own create, rename, move, second-marker and delete saves (2026-09-15, the `markers-a2*` goldens): 48-byte events like the arrangement's sections on the triple after the 0x11 one, names in `qSxT` records. `--add`, `--rename`, `--move` and `--delete` write those events and plain name records the way `arrangement --add` does, and Logic re-saved a copy carrying all four with both markers as written (`markers-edits-*`); Logic's own first marker also rewrote part of the registry, which ours leaves alone. A name outside ASCII is written as UTF-8, which Logic's Marker List showed and its re-save kept; Logic's own rename to one, an RTF record, is read (`names-text-*`, 2026-10-02). On a Logic 13.0 save (format 2514) `--add` came back from Logic 13.0's re-save byte for byte (2026-11-12, `markers-ours-resave-13-0-logic`). Also on 2514 (2026-11-13): `--rename` with `--move`, and `--delete`, each came back byte for byte (`markers-edit-ours-resave-13-0-logic`, `markers-delete-ours-resave-13-0-logic`). Also writes Logic 13.0's saves (file format 2514).

### `quantize-drums`

The drum-quantize procedure as file writes: groups off, the drum group with Editing (Selection) and Quantize-Locked (Audio), Q-Reference on the reference tracks, flex Slicing, and per region the two anchors plus one flex marker per hit found in the reference audio, targets on the grid, with the RBA Sequence carrying the Quantize value. Every layout is from Logic's own saves of one take (2026-09-13). Logic opened a written copy of that take reading Quantize 1/16 Note with Flex on, and its re-save kept every marker list, header, group and object field byte for byte. The hits are ours: the detector finds 78% of the transients Logic marked on that take across four grids and 88% of its own are among them, so the result is a quantize, not Logic's. The reference audio is 16/24/32-bit PCM or 32/64-bit float WAV; `--grid` takes the measured 4, 8, 16 or 32; a song whose tempo changes and reference audio with no hits are refused. `--bars FIRST-LAST` moves only the hits in those song bars onto the grid (each region's own Quantize value unless `--grid`) and keeps every other marker block's bytes, writing a kept Quantize-Off block as a hit block with its target unchanged; it refuses a region off the song's grid, a hit whose target would cross a kept one, and an entry naming a sequence other than an RBA Sequence, and a region already quantized keeps its one RBA Sequence. A member listing only anchors — Logic's first quantize writes the hits on the first Q-Reference region alone — takes that region's hits, and the group is reused when every member with audio regions is in it; on a take Logic itself quantized this wrote one list to every member, and Logic re-saved that `--bars 9-12` copy with every member's marker list and the drum group as written (2026-09-15, `songb-bars-9-12-*`), and those bars listen as tight as Logic's own. On a Logic 13.0 save (format 2514) a two-track take quantized to the 1/16 grid was re-saved by Logic 13.0 with the group, the markers and every region as written; on opening the copy Logic analysed the audio and appended its `LGBM` beat-marker cache to the two WAV copies inside the package, in place, and its save wrote their file records' size words and a word at magic+394 (1 → 3) for it (2026-11-13, `quantize-drums-ours-resave-13-0-logic`). Also writes Logic 13.0's saves (file format 2514).

### `strip-silence`

Cuts the silent stretches out of the named tracks' audio regions and fades the cut edges. Each audio file is read once into a peak per 10 ms (its top 16 bits); a stretch is silent while it sits under the file's 95th-percentile peak by more than the `--threshold` figure (default -30 dB, given at or below 0) for at least `--min-gap` s (default 2), and a sound shorter than `--min-keep` s (default 0.5) between two such stretches is silence too; `--pad` may differ before and after; with `--against-band` a sound is kept only if `--tilt` dB louder in `--tilt-band` (default `--band`; `auto` reads the file's fundamental at its loudest moments, 5 Hz steps from 50 to 350 Hz) than in that band at its peak (a tom's fundamental against the snare's range); `--spec FILE.json` cuts groups of tracks with their own settings in one run; a gap's edges then crop outward over sound under the loud level by more than the `--edge` figure (default -20 dB, at or above the threshold), a click of under 50 ms stepped over. Each kept span is widened by `--pad` ms (default 500); the region is split at the end of one span and the new piece's start trimmed to the next, a region that begins or ends in a gap is trimmed, `--fade` ms (default 20) goes in and out on every edge cut, and a region silent throughout is muted, there being no region delete. Every edit is `regions`' own split, trim, fade and mute, each of which Logic re-saved as written (2026-09-15). Logic 12.4 opened and saved a live set's copy cut with `--ref` on two vocal mics (2026-10-26); the code of 2026-10-28 writes every region entry as that save holds it but one piece's start, later in the save (a hand trim or the code since), and the region records differ in words Logic rewrites, not yet read. On a blank-born copy cut plain and with `--ref`, Logic 12.4's re-save holds every region entry and record as written but the payload `+130` it fills with the record's owner (`writers-a01-strip-silence-ours-resave-logic`, 2026-10-30). The split's registry pair is written only where the registry holds a run of them, which a recorded project's did not (2026-10-25). The loud level is the file's, so a file that is mostly silence sets it low and little is found; the plan names the level and the limit per region. With `--ref NAME` the rule is the bleed floor's instead: the mic's 25th-percentile nonzero level, on a 300 ms running median (`--window`, 50 for a drum's own hits), while the reference plays, and it is heard `--above` dB (default 9) over that (`--gate` sets this margin apart) and, bleed rising with whatever plays, over the bleed the references predict — each scaled by the mic's usual ratio to it, summed — by the same margin; `--band LOW:HIGH` measures an RMS within the band through `bandrms.swift` (a fourth-order Butterworth each side, checked against two tones). On one live set's vocal mics against an overhead, the lead mics separated from the bleed by a clear valley; the backing mics, given the lead mics as references too, by their rise over the bleed those predict (measured 2026-10-25). A tom mic's copy was opened in Logic 12.4 and heard (2026-10-25). `--above`, `--gate`, `--window` and `--against-band` need `--ref`, `--tilt` and `--tilt-band` need `--against-band`, a reference named twice or a cut track named as a reference is refused, as are a band reaching half the sample rate, a file at another rate than the project, a region the plan would cut that is crossfaded into or from another on its track, and a figure past a day of seconds, an hour of ms or 200 dB. The region's own fade-in and fade-out stay on its first and last piece, shortened to fit a piece they outlast, and a cut edge takes `--fade` with no curve or type. An entry numbers its file's pieces in two bytes (Logic 12.4's own save of a live set numbers pieces well past 255, 2026-10-25), so a file the cuts would take past 65535 is refused before anything is written. On a Logic 13.0 save (format 2514) a track cut plain was re-saved by Logic 13.0 with every piece as written but the piece-number word 13.0 fills in each cut record (2026-11-13, `strip-silence-ours-resave-13-0-logic`). Also writes Logic 13.0's saves (file format 2514).

### `songs`

Finds a live set's songs where the named tracks — a bass DI, a kick, a snare — all go quiet, and writes one arrangement section per song, named from a setlist. Each file is read once into a peak per 10 ms; a track is quiet under its file's 95th-percentile peak by more than the `--threshold` figure (default -30 dB, given at or below 0), and wherever no region of it plays; a run of `--min-gap` s (default 0.5) with every track quiet is a gap, sounds under `--min-keep` s (default 0.3) absorbed; gaps less than `--merge` s (default 15) of playing apart are one stop; a stop of `--min-stop` s (default 10) separates songs; playing under `--min-song` s (default 45) is listed and left out. The plan prints the stops, the stretches with the setlist laid over them and, per listed break, the stop that follows; when the setlist and the stretches differ in number it says so and writes nothing. The sections are `arrangement --add`'s, which Logic 12.4 showed and re-saved for a set's sections placed by hand (2026-10-25); the rule found every song of a second set with the defaults, and Logic 12.4 opened that copy and the joins were checked by ear: good (2026-10-25); Logic 12.4's save of a set's `--breaks` copy holds its sections, touching, as written (`vocal-pieces-moved-logic`, 2026-10-25), and its re-save of a blank-born `--breaks` copy holds every section and region as written (`writers-a02-songs-breaks-ours-resave-logic`, 2026-10-30). It left a set whose songs run together unmatched (a stretch fewer than songs, over a stop too short to find), since a join with no full stop is not found. `--breaks NAME` writes a section over every stop as well, so the sections run contiguous, as `arrangement --fill` does, to the end of the last region on any track. A section already where a song plays is named and nothing is written, so a second run cannot write the songs twice. A changing tempo, an unknown track, a track with no audio regions, a file at another rate than the project, and a setlist with a break before its first song, two breaks in a row or no song are refused. On a Logic 13.0 save (format 2514) `--breaks` over a two-track set came back from Logic 13.0's re-save byte for byte (2026-11-13, `songs-ours-resave-13-0-logic`). Also writes Logic 13.0's saves (file format 2514).

### `split-sections`

Cuts the named audio tracks' regions at the edges of every arrangement section of one name and, with `--to`, puts the pieces inside those sections on another track, where they are in time: a live set's talk between songs off the lead vocal track and onto a talking track once the breaks are sections (`songs --breaks`, `arrangement --fill`). The edges inside a region cut it into spans inside and outside the sections; a span shorter than `--min-piece` s (default 1) stays with its neighbour, uncut, so a hand cut a beat off a section's edge is left alone; the plan names every cut, move and such sliver. The region's own fade-in and fade-out stay on its first and last piece, shortened to fit a piece they outlast, and the cuts carry none; a region the plan would cut or move that is crossfaded into or from another on its track is refused. The cuts are `regions`' split, which Logic re-saved as written (2026-09-15), and the move is `regions --to-track`, the entry's track object and row — what Logic's own drag of a piece onto another track changed, its record untouched (`vocal-pieces-moved-logic`, Logic 12.4, 2026-10-25). Logic 12.4 opened and saved a set's copy with its break pieces cut and moved onto the talking tracks (2026-10-25); the code of 2026-10-28 writes every region entry of it byte for byte as that save holds it, the records differing only in the split-link words Logic rewrites. On a blank-born copy, Logic 12.4's re-save holds every section, region entry and record as written but the payload `+130` it fills with the record's owner (`writers-a03-split-sections-ours-resave-logic`, 2026-10-30). A piece that would land over a region on the destination or over another piece this run moves there, a destination that is not an audio track or is the track itself, `--to` naming fewer or more tracks than `--track`, an unknown section and a changing tempo are refused. On a Logic 13.0 save (format 2514) a take cut at two sections with the pieces moved onto Audio 2 was re-saved by Logic 13.0 with every piece and section as written; 13.0 filled the piece-number word of each cut record and flagged the destination row as holding a region (`+2` 0x14, `+43` 0x0c), which `--to-track`'s move writes too, so a fresh write differs in the piece numbers alone (2026-11-13, `split-sections-ours-resave-13-0-logic`). Also writes Logic 13.0's saves (file format 2514).

### `drums-to-midi`

Each `--hit TRACK=TERM` audio track's hits, found by `quantize-drums`' detector, become sixteenths on the term's key in the drum map, each cut at the next note on that key, velocity from each hit's peak scaled from the track's quietest to its loudest, quantized to `--grid` when given, in one new region on a software instrument track spanning the bars that hold the quantized notes; `--threshold DB` sets the detector's floor under the track's loudest hit, `--hit TRACK=TERM:THRESHOLD` one track's own, and `--velocity FLOOR..CEILING[:GAMMA]` maps the velocities onto a band. The region is written as `midi --region` writes one and filled through the region edits, and tempo changes are refused. Logic re-saved a copy carrying the region it wrote over a real drum take with all 350 notes as written (2026-09-15, `songb-drums-to-midi-*`). Listened to on that take: the kick and snare lanes are the playing. It is for drums with strong transients — kick, snare, toms; hats and cymbals ring under bleed and are not what this converts (the detector's 24 dB rise, not its floor, is what a hat never gives). On a Logic 13.0 save (format 2514) six hits made a kick region on the instrument track and came back from Logic 13.0's re-save with every note as written but two event lines of the region's sequence record in the other order (2026-11-13, `drums-to-midi-ours-resave-13-0-logic`). Also writes Logic 13.0's saves (file format 2514).

### `sessionplayer`

A Session Player region's settings from the JSON in its MneG record — Complexity (`rComp`), Fill Amount (`fillsAmount`) and Swing pinned by one editor move per save (2026-09-13) — with the drummer, preset and the generated notes' count. One region measured; records pair with drummer sequences in file order.

### `automation`

Reads track automation: the per-channel `*Automation` folders under the Track Automation Root Folder, their fader points (0x50: value byte, fader id) and plug-in parameter points (0x51-0x5F, 0x50 plus the mixer slot with empty slots counted, an instrument channel's instrument insert 1: a u32 over 2^31 and the parameter index; bit 14 of the type word, on some points of a real song, reads as flagged), and a region's own automation as the unreferenced sequence that names the track (2026-09-16, the `automation-*` goldens). Points were made with Create 1/2 Automation Point(s) for Visible Parameter (at the selected regions' borders) and in the Automation Event List, where Pan and the relative Volume lane were measured (the relative lane sets bit 7 of the type word's high byte). `--set`, `--copy` and `--clear` write a lane's points as the Event List does, in Logic's own order, into the track's existing folder; Logic listed three lanes written onto the blank as written and re-saved the folder byte for byte but for head +15, its selection state (`automation-ours-resave-logic`). A point's sub-tick fraction (head +2) is read and kept on a copy; Logic's own Automation Event List, read off the screen for every automation golden (2026-09-17), shows the same ticks and values as the reader, the half-tick point as the display tick before it. `--set "TRACK:slot N NAME=V@BAR"` writes a plug-in lane by mixer slot and parameter name in the parameter's own unit: the four natives with a map through their measured sliders (a value past a slider's end held there with a note), a third-party through its AU table (`autoset-*`); a value or bar that is not a finite number is refused. ## The two rules that matter most

**1. `apply-template` pairs by object id within a lineage and by a map across one; without a map it refuses.**
`services/mixer/pairing.py` pairs on Environment object id, then mixer label, then name. Two
unrelated projects both have an `Audio 1`, so the label rule pairs them happily: on one legacy song
that meant renaming *Guitar 1* to *Kick In* and *Bass* to *Snare Up*.

`match_quality` scores the share of rows paired by object id, and the command refuses below
`LINEAGE_FLOOR` (0.5). Songs cut from one recording template score 1.00; the legacy
songs score 0.02 and are refused by name, with an example of what would have been
renamed. `--force` overrides, and says so loudly.

A session with a few tracks remade by hand loses only a few points, which is why the floor sits
at 0.5 rather than near 1.

**2. Every write is gated, but a gate is not an audition.** `services/stream/integrity.py` holds
a project against the input it was given and refuses on any regression — new record-level
problems, more sequence link errors, objects whose mixer index stopped matching their channel,
channels whose send flags stopped matching their sends, a strip reference placed outside its
channel's records. It runs in `_edit.edit_copy` — the
path every `ProjectData` writer takes except `retrack --map` — and in `chains`, before the write
and again by reading the file back. A refused run discards the whole copy rather than leaving a bundle that
disagrees with its own metadata.

Proof it works: `apply-template` on a legacy song stops with `sequence link errors 0 -> 5`
rather than writing a corrupted project.

The gate covers structure, not sound. It cannot tell you a chain is on the wrong channel or
that the mix is wrong, so: **open every output in Logic before trusting it.**
